# Hands-On Learning Guide

This project is designed as an **engineering workshop**, not a pre-built template you only run.

## Core Rule

> **You build every file yourself** by following the lab manuals. All code lives inside the guides with full file paths and complete contents.

## What Changed vs a Typical Tutorial Repo

| Typical repo | This repo |
|--------------|-----------|
| Clone → `docker compose up` → done | Clone → read labs → **create folders/files manually** |
| Code only in `src/` | Code in **`docs/labs/`** (you copy into your tree) |
| AI scaffolds everything | AI teaches **incrementally** with test steps |
| Magic one-command setup | Every tool explained (Vite, Docker, Terraform, etc.) |

## Where Things Live

```
product-review-tracker/
├── docs/
│   ├── labs/              ← START HERE (lab manuals with FULL code)
│   ├── 00-MASTER-ROADMAP  ← Weekly schedule

├── backend/               ← YOU create this (Week 1 lab)
├── frontend/              ← YOU create this (Week 1 lab)
└── …                      ← YOU create per lab week
```

## How to Work Through a Lab

For each step in a lab manual:

1. **Read** PURPOSE and EXPLANATION
2. **Create** the folder if needed: `mkdir -p backend/app/routers`
3. **Create** the file: `touch backend/app/config.py` (or use your editor)
4. **Paste** the full CODE block from the lab
5. **Run** the TEST command for that step
6. **Compare** EXPECTED RESULT
7. If wrong → [14-TROUBLESHOOTING-GUIDE.md](./14-TROUBLESHOOTING-GUIDE.md), then `reference/` for that file only

## Lab Manual Format

Every file in labs uses this structure:

```
FILE:        exact/path/to/file.ext
PURPOSE:     what the file does
CODE:        complete file content (copy all of it)
EXPLANATION: beginner-friendly why/how
RUN:         command to test
EXPECTED:    what success looks like
MISTAKES:    common beginner errors
```

## Tooling: What Gets Generated vs What You Write

### Vite (`npm create vite@latest`)

| Generated by Vite | You care? | Action |
|-------------------|-----------|--------|
| `index.html` | Yes | Keep, may edit title |
| `vite.config.js` | Yes | Lab shows what to add (proxy) |
| `package.json` | Yes | Understand scripts: `dev`, `build` |
| `src/main.jsx` | Yes | Entry point — small file |
| `node_modules/` | Auto | **Never edit** — run `npm install` |
| `dist/` | Auto on build | **Ignore** — build output |

### Docker / Compose

| File | You write manually |
|------|-------------------|
| `Dockerfile` | Yes — every line in lab |
| `docker-compose.yml` | Yes — every line in lab |
| Image layers | No — built by `docker build` |

### Terraform

| File | You write manually |
|------|-------------------|
| `main.tf`, `variables.tf`, `outputs.tf` | Yes |
| `.terraform/` | Auto — **gitignore** |
| `terraform.tfstate` | Auto — **never commit** |

### GitHub Actions

| File | You write manually |
|------|-------------------|
| `.github/workflows/deploy.yml` | Yes — full YAML in lab |

## Incremental Implementation (Not Big Bang)

Labs are split into **small checkpoints**:

- Week 1: config → database → model → one endpoint → full CRUD → frontend shell → UI
- Week 2: one Dockerfile at a time, then compose
- Week 3+: one Terraform resource group at a time

After each checkpoint you **run something** and see output before continuing.

## Using the Reference Folder

`reference/` is the **answer key**. Rules:

1. Complete the lab step first
2. Only open reference for the **same file path** you are stuck on
3. Do not bulk-copy the whole project on day one

## Resume / Portfolio

Your portfolio story is stronger when you can explain **every file you created**. Interviewers ask "walk me through your architecture" — labs prepare you for that.
